Why PDF is the worst format to hand to a stranger's server

Think about what people actually merge and split. Signed contracts. Scanned passports for a visa application. Medical records. Bank statements for a mortgage. Tax paperwork. Almost nobody splits a PDF for fun — it is nearly always a document with consequences attached.

The standard online PDF tool asks you to upload that file first. It then sits on infrastructure you cannot inspect, under a retention policy you have to take on faith, in a jurisdiction you probably did not check. Most of those services are honest. But the ones that were not have been the subject of enough breach reports that treating it as a non-issue is optimistic.

The technical point worth understanding is that server-side processing is no longer necessary for this. PDF manipulation runs perfectly well in JavaScript. When a service still requires an upload for a merge operation, that is an architectural choice, not a technical constraint.

Merging: order is the whole game

Merging concatenates documents in the order they are listed. The tool above uses the order you added the files, so if you drop in a folder, you inherit whatever order the operating system handed over — which is often alphabetical, and rarely what you wanted.

For anything where sequence matters, add the files one at a time in the order you want them. It takes a few extra seconds and saves redoing the whole thing.

A useful habit for documents that get merged repeatedly, like monthly reports: name the source files with a leading number — 01-cover.pdf, 02-summary.pdf, 03-appendix.pdf. Alphabetical then equals correct.

What carries over and what does not

Merging preserves the pages themselves — text stays selectable, images stay embedded, and the pages keep their original dimensions. Some structural features do not survive:

  • Bookmarks and outlines are generally lost, since each source file has its own tree and there is no unambiguous way to combine them.
  • Form fields can collide. Two documents each with a field named signature produce a conflict, and the result is unpredictable. Flatten forms before merging.
  • Digital signatures break. This is by design, not a bug — a signature certifies one exact byte sequence, and merging changes it. If you need a signed document to stay verifiable, keep it separate.

Splitting: how the page range works

Enter the pages you want to keep, using commas for separate selections and hyphens for ranges. Pages are numbered from 1, matching what your PDF reader displays.

  • 1-5 keeps the first five pages.
  • 1, 4, 9 keeps three individual pages.
  • 1-3, 8, 12-14 mixes both, and the output follows that order.

Anything not listed is dropped from the output. The original file on your disk is never modified.

Splitting does not redact

This is worth being blunt about, because getting it wrong has ended careers. Removing a page removes that page. It does not remove sensitive content from pages you keep.

If your goal is to hide information rather than drop whole pages, drawing a black box over text in a PDF editor does not work either — the text is still in the file underneath, and anyone can select and copy it. Proper redaction requires a tool that deletes the underlying content, or, as a crude but reliable fallback, printing the page to an image and rebuilding the PDF from that.

File size after merging

The output is roughly the sum of the inputs, occasionally a little smaller where identical resources get shared. Merging does not compress anything.

If the result is too large for an email attachment, the size is almost always coming from scanned pages — a scan is a full-page photograph, and at 600 DPI a single page can run several megabytes. The fix is to reduce the scan resolution before merging rather than to compress afterward. 300 DPI is plenty for text documents, and 200 is usually still legible.

When a browser tool is the wrong choice

Everything here is held in memory, which sets a practical ceiling. A few hundred megabytes of PDF will make a desktop browser struggle and will likely crash a phone. Signs you have hit the limit are the tab freezing or the operation never completing.

For genuinely large jobs, or for batch work across hundreds of files, desktop software or a command line tool is the better answer. For the ordinary case — combining five documents into one attachment, pulling three pages out of a report — a browser handles it fine and without the upload.

Questions

Are my documents uploaded to a server?

No. The PDF is read and rewritten in this browser tab using JavaScript. You can verify it by opening developer tools, switching to the Network tab, and running a merge — no request carries your file.

Is there a file size limit?

No fixed limit, but everything is held in your device's memory. Files totalling a few hundred megabytes will strain a desktop browser and are likely to crash a phone.

Can I merge a password-protected PDF?

Not directly. Encrypted PDFs cannot be read without the password being supplied to the parser. Remove the protection in your PDF reader first, then merge.

Will merging break a digital signature?

Yes, always. A signature certifies one exact version of a file, so any modification invalidates it. That is the signature working correctly. Keep signed documents separate if verification matters.

How do I control the order when merging?

Files are merged in the order you add them. Add them one at a time for full control, or name them with leading numbers so that alphabetical order matches the order you want.

Does splitting a PDF remove sensitive information?

Only from pages you drop entirely. Content on pages you keep is untouched. Splitting is not redaction, and drawing black boxes over text does not remove the underlying text either.
