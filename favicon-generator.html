What a favicon set actually needs in 2026

Favicons accumulated a lot of cruft over two decades. At one point the recommended set ran to more than twenty files, covering Windows tile icons, a dozen Apple device resolutions, and formats for browsers that no longer exist. Most of that is now dead weight.

The set this tool produces is the modern minimum that still covers everything with real usage:

  • favicon.ico , 16, 32 and 48 pixel versions bundled in one file. Still needed because browsers request it from the site root whether you reference it or not, and because it is what appears in bookmark lists and some address bars.
  • favicon-32.png and favicon-16.png , what modern browsers actually display in the tab.
  • apple-touch-icon.png at 180×180 , used when someone adds your site to an iOS home screen. iOS ignores the ICO entirely.
  • icon-192.png and icon-512.png , Android home screen and the PWA install prompt. The 512 is also what gets used in app switchers and splash screens.
  • site.webmanifest , tells Android which icons to use and what to call the app.

Six image files and one JSON file. That covers Chrome, Safari, Firefox, Edge, iOS, and Android without carrying files nothing requests.

Why the .ico file contains three images

ICO is a container format, not a single image. One .ico can hold several resolutions, and the operating system or browser picks whichever fits the context it is drawing into. A browser tab wants 16px. A bookmark bar might want 32. A Windows desktop shortcut reaches for 48.

If you only supply a single large image and let the browser scale it down, small sizes come out muddy , downscaling a detailed 512px logo to 16px by algorithm produces a grey smear. Generating each size separately means each one is encoded from the source at its target dimensions, which is noticeably sharper at the sizes that matter most.

Design for 16 pixels, not for 512

This is the mistake almost everyone makes. A logo that looks great on a business card usually fails completely at 16×16, because at that size you have roughly the detail budget of a single letterform. Wordmarks become illegible. Thin strokes disappear. Gradients turn into flat mud.

What survives: a single bold letter, a simple geometric mark, high contrast between subject and background. Generate the set, then look at the 16px preview at actual size. If you cannot tell what it is, simplify the source image rather than accepting the result.

SVG source versus PNG source

Feeding in an SVG generally gives sharper results, because each size is rasterised from vector geometry at its target resolution rather than resampled from a fixed grid of pixels. If you have the original vector, use it.

Two caveats. SVGs referencing external fonts will render with fallback fonts, since the font is not embedded , convert text to outlines first. And SVGs relying on CSS defined outside the file itself will lose that styling.

If you only have a PNG, start from at least 512×512. Upscaling a 64px logo produces a soft 512 icon and there is no recovering detail that was never captured.

Where the files go

Put all six images and the manifest in your site root , the same folder as index.html. The root matters specifically for favicon.ico, because browsers request /favicon.ico directly regardless of what your HTML says. Then paste the generated snippet into your <head>.

If your site lives in a subdirectory, change the leading / in each path to a relative path instead.

Why your new favicon still is not showing

Favicons are cached more aggressively than almost anything else on the web, and a normal refresh will not clear one. This causes an enormous amount of confusion.

  • Hard reload first , Ctrl+Shift+R, or Cmd+Shift+R on Mac.
  • Load the file directly , visit yoursite.com/favicon.ico. If the old icon appears there, it is a cache issue. If you get a 404, the file is in the wrong place.
  • Try a private window , this bypasses the favicon cache entirely and shows you what a new visitor sees.
  • Give it time , some browsers hold favicons for days regardless of what you do. If it works in a private window, it is working; your own browser is just being stubborn.

Questions

What size should my source image be?

At least 512×512, and square. Anything smaller means the large icons are upscaled and will look soft. If the source is not square it gets letterboxed rather than stretched, so crop it first.

Do I still need favicon.ico?

Yes. Browsers request /favicon.ico from your site root automatically even when your HTML points elsewhere. Without it you get a 404 in your logs on every visit, and some contexts fall back to a blank icon.

Can I use a transparent background?

Yes, and it usually looks best in browser tabs. One exception: iOS ignores transparency on the Apple touch icon and composites it onto black, so if your logo is dark, set a background colour.

Why does my favicon look blurry?

Usually the source was too small and got upscaled, or the design carries too much detail for 16 pixels. Start from a 512px original and simplify the mark until it reads at small size.

Is the manifest file required?

Only if you want Android home screen icons or a PWA install prompt to work properly. It costs nothing to include, so there is little reason to leave it out.

Are my brand files uploaded anywhere?

No. Everything is rendered and encoded in this browser tab. You can confirm it in the Network tab of developer tools , no request carries your image.
